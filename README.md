# Candy Night · 4×4 Flip Planner

[Open the live app](https://weilelins.github.io/candy-night-planner/) · [GitHub repository](https://github.com/weileliNS/candy-night-planner)

GitHub Pages 版本界面使用英文，包含 Planner 与 Simulation 页面。已按展示需求移除棋盘记录、文本导入/复制及样本按钮区域；模型层的原始样本、文本格式函数与相关测试仍保留用于验证。右上角 **Expected tokens** 显示当前策略的预计剩余代币成本 `5 × V(S)`，不含已经花费的代币；近似模式下为估计值，启发式未估值时显示 `—`，通关后为 `0.0`。

在本地浏览器记录翻牌结果，计算隐藏保底线的贝叶斯后验，并规划通关所需的期望剩余翻牌次数。React + TypeScript + Vite，计算和模拟均运行在 Web Worker，无后端或外部服务依赖。

## 启动

需要 Node.js 22.12+ 或 24+（Vitest 5 的运行要求），推荐 Node.js 24。

```sh
npm install
npm run dev
```

打开终端显示的地址，默认 `http://127.0.0.1:5173`。静态生产构建用 `npm run build`；部署 `dist/` 时需使用 HTTP 服务器，不能直接双击 HTML（浏览器 Worker / module 限制）。

```sh
npm test
npm run validate -- 1000 1000
```

第二条命令对六个 p、六种策略运行模拟：1000 为目标局数，第二个 1000 为每个 p × 策略的毫秒预算。输出写入 `validation/simulation.json` 和 `validation/samples.json`。机器性能会改变实际完成数量和近似采样数，必须看 n。界面支持 1000 / 10000 / 100000 局和结果 CSV 导出。

## 使用

1. 点击格子按 U → C → E → U 循环；坐标从 R1C1 开始。
2. 推荐格以星标、文字和边框标记。百分比为未知格的糖果边际概率，虚线圈出当前整线成功概率最高的线（并列只显示一条，鼠标悬停候选表可查看其他线）。
3. 推荐区的 Q 包含下一次点击成本；当前最优值等于最小 Q，仅在 Exact 模式有最优保证。Approximate 显示所选续行策略的估计值。并列时按格子索引选择。
4. 可使用 Undo、Redo、Reset。状态与设置自动写入 localStorage，刷新恢复。
5. 自动模拟开关生成一张隐藏棋盘并逐步执行推荐；手动修改或改变参数会停止模拟。不会向真实游戏执行点击。
6. 调整 p、保底线先验权重、精确和近似预算。p 的范围包括 0 和 1。权重会自动归一化；不允许全部为 0。
7. 参数敏感性分析使用当前同一观测状态分别计算六个 p。

## 模型：假设，而非已确认游戏源代码

从十条合法四格线中按先验选择 H，H 上全是糖果，另外十二格独立 Bernoulli(p)。十条线是四行、四列和两条对角线。只需实际翻出任意完整线，不必辨认原始 H。推断某格必为糖果也仍须点击。

观察状态 S=(C,E)。若 H 与 E 相交，似然为零；否则

`P(S | H=h) = p^(|C|-|C∩h|) (1-p)^|E|`。

对于 0<p<1，约去共同因子后，`P(H=h|S) ∝ prior[h] p^(-|C∩h|)`。实现采用 log-sum-exp 归一化。p=0 只允许 C⊆h 且 E∩h=∅；p=1 不允许出现任何 E，所有 C 都不提供 H 信息。无法解释的观测会报错，即使棋盘尚有未阻断线，也可能与边界参数或非均匀先验不相容。

未知格 x 的边际糖果概率为 `p+(1-p)Σ[h含x]posterior[h]`。代码先检查后验支持集：所有存活 H 均含 x 时直接返回 1，全不含时直接返回 p，避免浮点误差产生虚假的正概率分支。格子之间并不独立。

候选线 L 的整线糖果概率为 `Σ_h posterior[h] × p^|unknown(L)\h|`；若 L 已被空格阻断则为 0。它通常大于 L 是原始保底线的概率。此公式通过 H 条件化，不能用单格边际概率的乘积替代。

## 三种算法标签

**Exact Optimal**：完整 Bellman 递归：

`V(S)=0`（已完成）；否则 `Q(S,x)=1+P(Cx|S)V(S+Cx)+P(Ex|S)V(S+Ex)`，`V(S)=min_x Q(S,x)`。

仅展开正概率分支；使用两个 16-bit mask、按需 memoization，均匀先验时对八种 D4 旋转镜像取最小键。非均匀先验关闭此对称合并。缓存按 p 和完整先验隔离；单次搜索内复用已完成子问题。助手输入变化时会终止旧 Worker，缓存不跨输入保留；模拟的 Exact 策略可在同一 p 的各局间复用缓存。最多缓存 350000 状态，周期检查墙钟预算；只在所有根动作完整计算成功后显示 Exact。使用双精度，最优保证相对于所选概率模型与浮点误差，不是对真实游戏未知机制的保证。

**Approximate**：从当前后验采样完整隐藏棋盘。每轮让所有根动作使用同一张棋盘，之后通过合法、自适应的续行策略一直翻到通关；续行只访问已观察状态，不偷看隐藏结果来选动作。续行优先分数为 `整线成功概率 / 该线未知格数 + 0.025 × 当前格糖果概率`，在仍可完成且经过该格的线中取最大。比较各根动作的平均总成本，而非只比较下一格概率。

该方法是单步策略改进的 Monte Carlo rollout，不是完整 Bellman 最优。无全局次优界；即使采样无误差，续行策略也可能次优。每动作报告标准误及 `均值±1.96标准误`，是固定动作均值的渐近区间；未修正从多个动作中选最小导致的偏差，不包括模型误差和策略误差。只有一个样本时不显示区间；极少样本区间不可靠。配对采样减少动作差值的波动，但界面没有把单动作区间误称为动作差值区间。

**Heuristic**：只按最高糖果概率选格。没有估计通关成本，Q 和 V 显示 `—`，绝不标为最优。

默认 **自动模式** 先尝试完整精确搜索，超时或缓存达上限转近似，并明确显示 Approximate。用户强制 Exact 时失败会显示预算错误，不悄悄替换算法。初始局面的精确计算可能很贵；这是有限设备预算下的现实限制，不能因为有贝叶斯后验就声称找到了全局最优。

## 原始样本核验与 p 的限制

原始数据保留在 `src/model.ts`，没有偷偷修正。将 U 当作未揭晓但真实为糖果扫描十条线：

| 样本 | 未被 E 阻断的线 | 校验 |
|---|---|---|
| A | 第3列 | U 位于 R4C3，需翻开后通关 |
| B | 第2行 | U 位于 R2C4；原文字“第2列”错误，R4C2 是 E |
| C | 主对角线 | R1C1、R2C2、R3C3(U)、R4C4；原文字“第1列”及补充文字“第3列”均有误 |

所以不能从这三张矩阵验证“非保底格16糖果、20空格”的统计。A、B 在把 U 当糖果后均有10糖果、6空格；各自扣除唯一保底线得到6背景糖果、6空格。C 有9糖果、7空格，扣除唯一保底线得到5背景糖果、7空格。三样本合计17背景糖果、19空格，比例17/36≈0.4722；但存在样本少和选样偏差，**不据此擅自替换参数**。按要求默认 p=16/36，界面提示其未经验证，允许调整并做敏感性分析。三个矩阵本身都与保底模型相容，矛盾在人工标注和汇总统计；不要把该假设理解为已经识别了活动真实生成规则。

## 模拟的公平性与限制

每个 p 先用种子 20261028 生成同一组棋盘，再让六策略依次使用该组。比较 Random、Max Candy Probability、Max Information Gain（关于 H 的期望熵下降）、Line Completion Greedy、Exact Bellman、Approximate Planner。所有策略直到实际形成一条糖果线才停。

显示平均值、中位数、P90、P95、最坏已完成样本、平均代币、耗时和实际 n。百分位用 nearest-rank，中位数在偶数时取两中间值均值。模拟近似策略每步最多24次 rollout，8ms预算；与助手可配置的预算不同。Exact 一步最多1000ms，失败立即终止该组，已完成值都是真正精确策略。

预算按完成一局的边界检查，单步精确/近似计算会有小幅预算超出；统计耗时包含失败尝试。不同策略可能完成不同数量，不能直接对均值排名；“节省”只在该策略与 Random 共享的同一棋盘前缀内计算并展示配对数。若 Exact 初始局面超时，该组 n=0，其统计为缺失而非0次通关。进程内不为未完成局面填造数据。
